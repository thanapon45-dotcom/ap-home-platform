ยืนยันเส้นทางจากโค้ดและ ADR ณ commit ที่ระบุ การมีโค้ดไม่ยืนยันว่า deployment, credentials และ workflow ที่ active ทำงานครบแล้ว รอบนี้ไม่ได้รันงาน production

แบ่งหน้าที่ของระบบ

หน้าจอและ API · Next.js

รับคำสั่งเจ้าของระบบ แสดงผลและเลือก backend ให้แต่ละงาน ไม่ใช่แค่ proxy เข้า Hub อย่างเดียว

Hub v1 · server.cjs

จัดการ state, Blog/FB queue, callbacks, QC, Property และ BOQ ตาม route ที่มี เป็นเส้นทางหลักตาม ADR-004; env ที่ deploy ต้องตรวจแยก

n8n และ FB Backend

n8n ทำ workflow หลายขั้นและอาจเรียก AI/ฐานข้อมูลเอง FB Backend เป็นบริการแยกสำหรับการโพสต์ Facebook

Supabase และผู้ให้บริการ

Supabase เก็บข้อมูลธุรกิจ ส่วน WordPress/Facebook เป็นปลายทางเผยแพร่ Telegram/LINE เป็นช่องทางสื่อสารตาม integration

Hub v2 ต่างจาก v1 อย่างไร

v2 แยก domain, ports, use cases, adapters, AI gateway และ event bus เพื่อให้ทดสอบและเปลี่ยนผู้ให้บริการง่ายขึ้น แต่การจัดโครงสร้างแบบนี้ไม่ได้ทำให้เป็นผู้วิเคราะห์ธุรกิจครบวงจรเอง

รายการ v1 v2 ใน source
Header x-hub-token x-hub-secret
Blog queue /action/blog/queue/* /api/blog/queue/* มีใน blogRoutes.ts
FB queue /action/fb/queue/* fbRoutes.ts มี publish/state แต่ไม่มี queue build/clear/run-next
สถานะ เส้นทางหลักตาม ADR งานแยก; ยังไม่ถือว่าทดแทน production ได้ครบ

ขอบเขตการเชื่อมข้อมูล

Brains เป็นตัวอ่านรวมข้อมูลเดิม ไม่ใช่ฐานข้อมูลใหม่และไม่ได้ฝึกโมเดลเอง อ่าน market insights, summary, area memory, buyer signals, deals, QC และ content frames แต่ไม่อ่านประวัติแชท, projects หรือ BOQ ใน endpoint นี้

ตัวกรองพื้นที่ใช้กับ market insights, summary, area memory และ deals เท่านั้น ส่วน buyer signals, QC และ content frames ไม่ได้กรองตามพื้นที่ ค่า verified_insights หมายถึง confidence ≥ 4 ไม่ใช่การยืนยันโดยมนุษย์ จำนวนที่คืนเป็นผลค้นจำกัดจำนวนต่อแหล่งข้อมูล ไม่ใช่ยอดรวมทั้งระบบ

Assistant ส่งข้อความและประวัติในหน้าเว็บไป /api/assistant ซึ่งเรียก Claude Sonnet 4.6 และเลือก tools อ่าน Hub / Supabase / Brains ได้ คำสั่งเขียนมีเพียงรัน Blog กับ FB queue โดยมีปุ่มยืนยันก่อนเรียก

ประวัติอยู่ใน React state; reload แล้วไม่กู้แชทจากฐานข้อมูล ไม่มี tool สร้างหรือแก้ดีลจากแชท ข้อมูลสมมติในบทสนทนาจึงไม่ใช่ข้อมูลดีลที่บันทึกแล้ว

ข้อกำหนดห้ามตอบด้วยข้อมูลนอกระบบอยู่ใน prompt แต่โค้ดยังส่งข้อความที่โมเดลสร้างกลับมา จึงยังไม่ใช่การบังคับคำตอบจากหลักฐานฝั่งเซิร์ฟเวอร์อย่างสมบูรณ์ ปุ่มยืนยันคำสั่งไม่ทดแทนระบบตรวจสิทธิ์ผู้ใช้
