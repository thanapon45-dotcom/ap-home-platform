04 · Assistant จำอะไรได้ในปัจจุบัน

ยืนยันจากโค้ด

จำได้ระหว่างหน้าเว็บยังอยู่

  • ข้อความอยู่ใน React state: displayMessages และ apiMessages
  • แต่ละคำถามส่งประวัติใน state ไปให้ API อีกครั้ง
  • ย่อช่องแชทแล้วเปิดใหม่ในหน้าเดิม ประวัติยังอยู่
  • เมื่อ reload / เปิดหน้าใหม่ ไม่มีระบบกู้ประวัติแชทจากฐานข้อมูล
ข้อเสนอ — ยังไม่ได้ทำ

ความจำถาวรที่ควบคุมต้นทุน

  • เก็บข้อความในฐานข้อมูลเดิมหลังตรวจพื้นที่และสิทธิ์เข้าถึง
  • เลือกเฉพาะประวัติที่จำเป็นส่งให้ AI ไม่ส่งทุกบทสนทนา
  • แยกข้อมูลดีลที่ยืนยันแล้วออกจากตัวเลขสมมติในแชท
  • ผูกแชทกับดีลให้ชัด และให้ยืนยันก่อนแก้ข้อมูลหลัก
  • ยังไม่เพิ่มการเรียก AI สรุปทุกข้อความ
พิมพ์ข้อมูลบ้านในแชท ไม่ได้ทำให้เกิดดีลใน /deals อัตโนมัติ API ปัจจุบันมี tool อ่านดีล แต่ไม่มี tool สร้างหรือแก้ดีล การบันทึกข้อมูลธุรกิจกับการเก็บประวัติแชทเป็นคนละเรื่อง

Assistant ใช้ claude-sonnet-4-6, จำกัด output ต่อการเรียกไว้ 4,096 tokens และวน tool loop ได้สูงสุด 6 รอบต่อ request หนึ่งคำถามจึงอาจมีหลาย AI calls โค้ดยังไม่มีบัญชีค่าใช้จ่ายกลางหรือการตัดประวัติตามงบ

คำตอบต้องอิงข้อมูลจาก tools หรือข้อมูลที่ผู้ใช้ระบุ หากขาดข้อมูลให้ถาม ไม่เติมตัวเลขจากความรู้ทั่วไปนอกระบบตามกติกาเจ้าของระบบ ข้อกำหนด internal-only ยังอยู่ใน prompt; โค้ดส่งข้อความจากโมเดลกลับมา จึงยังไม่ได้บังคับคำตอบจากหลักฐานฝั่งเซิร์ฟเวอร์ครบถ้วน สถานะนี้อ้างอิง application code ไม่ใช่คำรับรองนโยบายเก็บข้อมูลของผู้ให้บริการ AI

05 · WF1 และ AI Quality Gate

ADR-016 amendment merge แล้ว

หัวข้อ Content ≠ บริการที่ขาย

บทความสร้างบ้าน แบบบ้าน ค่าใช้จ่าย และเลือกผู้รับเหมาทำได้ บล็อก brand_guardrail_violation เมื่อเนื้อหาหรือ CTA อ้างว่า Finnhouses รับจ้างสร้างบ้านให้ลูกค้า ต้องอ่านบริบทและมีข้อความหลักฐานจริง

ยังต้องตรวจภาษาไทย ข้อเท็จจริง และ structural / dedupe guard ตามเดิม มีตัวอย่างด้าน brand 13 กรณีใน ADR

ยังไม่ยืนยัน active n8n revision

เอกสารเปลี่ยนแล้ว ≠ workflow เปลี่ยนแล้ว

PR #3 merge แล้ว (ea4565f) แต่รอบนี้ไม่ได้ import / activate หรือทดสอบ prompt บน n8n การมีไฟล์ WF1 ฉบับแก้ไขแยกต่างหากไม่ยืนยันว่า instance ใช้ฉบับนั้น

ต้อง export ตัว active และตรวจ writer / gate ก่อนยืนยันผล production

ลำดับตาม ADRหน้าที่เมื่อไม่ผ่าน / ข้อจำกัด
รับงานและสร้างบทความใช้ keyword / category และสร้าง payloadต้องใช้ business context เดียวกับ reviewer
ตรวจสองทางStructural guard + AI Quality GateAI ตรวจ brand, ภาษาไทย และ unsupported claims
Parse / Log / Combineรวมเหตุผล และบันทึกการตัดสินใจลง quality_gate_logADR เดิมกำหนด AI infra/parse error เป็น fail-open; ไม่ได้เปลี่ยน policy นี้ใน amendment
ผ่าน / บล็อกผ่านจึงเข้าสู่ทางเผยแพร่; บล็อกเข้าสู่ทางแจ้งผลผัง node และ connection ที่ active ต้องตรวจจาก export จริง
Human feedbackยืนยันถูก / ผิดผ่าน Quality Gate dashboardการกดยืนยันไม่ได้ปรับ prompt หรือฝึกโมเดลอัตโนมัติ

Snapshot จากเจ้าของระบบวันที่ 21 ก.ย. 2026: 47 ครั้ง, ผ่าน 1 / บล็อก 46, ถูก 25 / ผิด 22, accuracy 53.2%, false positive 22 / false negative 0 — ไม่ใช่ผลหลังแก้ และยังไม่ได้ตรวจบทความเต็มทั้งชุด API accuracy อ่านล่าสุดไม่เกิน 200 แถว จึงไม่ใช่ยอดตลอดอายุระบบเมื่อเกินจำนวนนี้

06 · ค่าใช้จ่ายที่เจ้าของระบบแจ้ง

รายการUSD / เดือน

AI รวม $10/เดือน แยกจาก Railway ตัวเลขนี้เป็นยอดที่เจ้าของระบบแจ้ง ไม่ใช่ invoice ที่ตรวจแล้ว และไม่ใช่ hard cap ที่ระบบบังคับอยู่

ยังไม่มีเพดานรวมที่ยืนยันได้

มีตัวคุมเฉพาะ QC

QC มี qc_daily_usage เก็บ tokens และต้นทุนประมาณการ โค้ดตั้งค่าเริ่มต้น QC_DAILY_BUDGET_THB = 300 บาท/วัน อาจมี env บน server ทับค่าอยู่ ซึ่งยังไม่ได้ตรวจ

Assistant, chat และ image routes ที่ตรวจไม่บันทึกค่าใช้จ่ายรวมทุกผู้ให้บริการ และไม่มี monthly budget gate ร่วมกัน

n8n ใช้แบบฟรีตามที่เจ้าของระบบแจ้ง แต่การเรียก AI จาก workflow ใช้บัญชี API ของผู้ให้บริการแยกกัน ห้ามนับว่า AI ฟรีตาม n8n และไม่เพิ่มค่า Railway อีกก้อนโดยไม่มีบิลรองรับ

สิ่งที่ต้องมี ก่อนรับรองว่าคุมค่าใช้จ่ายได้จริง
  1. เทียบ Usage / Billing ของทุกบัญชี AI กับงานที่รันจริง รวม retry, fallback, ภาพ และ n8n
  2. เก็บ usage ต่อ request, provider, model และงาน โดยแยกยอดประมาณการกับยอดเรียกเก็บจริง
  3. กำหนดวงเงินร่วมและจองงบก่อนเรียก เพื่อคุมงานที่รันพร้อมกัน
  4. ยืนยันวงเงินกับเจ้าของระบบจากฐานค่าใช้จ่ายล่าสุด ไม่ใช้เพดานรวม $15 ที่เกิดจากความเข้าใจผิดก่อนหน้า

ทั้งหมดเป็นงานที่ยังไม่ได้ implement; ไม่รับรองว่าบันทึกแชทแล้วค่าใช้จ่ายจะเท่าเดิมจนกว่าจะตรวจพื้นที่และ token usage
