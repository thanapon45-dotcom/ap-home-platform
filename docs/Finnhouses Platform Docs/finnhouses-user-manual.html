Module 2

👥 CRM — Lead Kanban

จัดการ leads ทั้งหมดแบบ drag-and-drop — ข้อมูลบันทึกลง Supabase ทันที

Stageความหมายทำอะไรต่อ
new — New Leadเพิ่งเข้ามา จาก Budget Toolโทรติดต่อภายใน 24 ชม.
followup — Follow Upติดต่อแล้ว รอ appointmentนัด site visit
qualified — Qualifiedผ่านการคัดเลือก กำลัง proposeส่ง BOQ / proposal
closed — Closed ✅ปิดงานแล้วเริ่มกระบวนการก่อสร้าง
วิธีใช้ CRM
1
Drag card ข้ามคอลัมน์
ลากการ์ด lead จาก stage หนึ่งไปอีก stage — Supabase อัพเดทอัตโนมัติ
2
คลิกการ์ดเพื่อดูรายละเอียด
ดู budget, style, notes, เบอร์โทร
3
เพิ่ม notes
บันทึกสิ่งที่คุยกับลูกค้า — n8n CRM Note Parser จะ parse ทุกคืน 22:00 และส่ง insight ทาง Telegram
🤖 CRM Note Parser — Auto ทุกวัน 22:00 LIVE
n8n ดึง leads ที่มี notes → Claude Haiku parse → บันทึก intent + urgency + buyer_context_signals → Telegram digest
ช่วยรู้ว่าต้องโทรหาใครก่อน และ buyer กำลังคิดอะไรอยู่
Module 3

✨ AI Content Studio LIVE

สร้าง Facebook content ด้วย AI — 6 tabs ทำงานต่างกัน

Tab 1: สร้างจาก Keyword ⭐ ใช้บ่อยที่สุด
1
เลือก Keyword
เลือกจาก dropdown หรือพิมพ์ keyword เองในช่อง "หรือพิมพ์เอง"
2
เลือกกลุ่มลูกค้าเป้าหมาย 🆕 (ADR-009/010)
ฝากขายบ้าน (resale) หรือ ที่ปรึกษา/ตรวจสอบ (inspection) — เลือกได้อิสระทุก Tone (ไม่มี Style บ้านให้เลือกแล้ว เลิกใช้ตั้งแต่ ADR-010)
3
เลือก Tone
เป็นกันเอง / มืออาชีพ / Educate / สนุก / ดึงใจ / 3T Story / 🎯 Positioned
4
กด ✨ Generate
AI สร้าง FB Post ภาษาไทยให้ทันที
5
Copy / Save / Post to Facebook
กด Copy เพื่อคัดลอก · Save เก็บลง History · Post to Facebook โพสต์ทันที
🎯 Positioned Mode — เลือก Tone = "🎯 Positioned"
กลุ่มลูกค้า (2 กลุ่มจริง — อัปเดต ADR-010, เลิกอ้างอิงธุรกิจรับสร้างบ้านแล้ว):
· 🏠 ฝากขายบ้าน (resale) — กลัวเลือกผิด/เสียเวลาดูทรัพย์ไม่ตรงใจ → เล่าชีวิตที่ดีขึ้นเมื่อได้บ้านที่ใช่
· 🔍 ที่ปรึกษา/ตรวจสอบ (inspection) — กลัวจุดที่มองไม่เห็นด้วยตาเปล่าตอนโอนบ้าน → "ให้มืออาชีพตรวจก่อนเซ็นรับ"

Awareness Level: Unaware → Problem Aware → Solution Aware → Most Aware
Timing Signal: โบนัสออก · ดอกเบี้ยขึ้น · หน้าฝน · ปีใหม่ · เพิ่งแต่งงาน · มีที่ดินแล้ว
Tab 2: แปลงจาก Blog
วาง URL บทความจาก finnhouses.com → กด "ดึงบทความ" → AI แปลงเป็น FB Post + ดึงรูป featured image → กด "Post to Facebook"
Tab 3: จาก Listing
เลือกทรัพย์จากรายการ → AI สร้าง FB Post โปรโมทพร้อมราคา จุดเด่น และ CTA ลิงก์ทรัพย์โดยตรง
Tab 4: History & Status — ⭐ Taste Library
ดู content ที่ save ไว้ทั้งหมด

Taste Library: กดดาว ☆ บน content ที่ดี → พิมพ์ "ทำไมถึงใช่?" → Enter
Content ที่ star ไว้ (max 2) จะถูก inject เป็น example ให้ AI → output ดีขึ้นเรื่อยๆ
Tab 5: Content Queue 📅
วางแผน FB Posts 7 วันล่วงหน้า → n8n รันทุกเช้า 09:05 โพสต์อัตโนมัติ

วิธีใช้: กด "สร้าง Queue 7 วัน" → แก้ข้อความแต่ละวัน → "บันทึก Queue 7 วัน"

⚠️ FB Queue ไม่ auto-refill — ต่างจาก Blog Queue ที่เติมให้เองอัตโนมัติ ถ้า FB Queue ว่าง ระบบจะแค่ส่ง Telegram แจ้งเตือน คุณต้องเข้ามาสร้าง Queue ใหม่เอง (ตั้งใจให้เป็นแบบนี้ — คุณเลือกคุมเนื้อหา FB เอง)
Tab 6: 🧠 Market Intel UPDATED
บันทึกสิ่งที่เห็นในตลาดโดยตรงจาก UI — ไม่ต้องผ่าน console

วิธีใช้:
1. เลือก Area (พื้นที่) · กรอก Lat/Lng (ถ้ามี, ไม่บังคับ)
2. พิมพ์สิ่งที่เห็น/ได้ยินในตลาด
3. กด Submit → parse → บันทึก Supabase → Claude สร้าง Positioned Content → Telegram

ตัวอย่าง: "ลูกค้าลาดหลุมแก้วถามเรื่องน้ำท่วมก่อนเลย" · "ช่วงโบนัสออกมีคนทักเยอะผิดปกติ"

Module 7

🔍 QC Line (LINE OA) LIVE

ช่างหน้างานส่งรูปผ่าน LINE → AI Vision ตรวจสอบคุณภาพงานทันที ตอบกลับเป็นภาษาไทยภายใน ≤15 วินาที

Flow การตรวจ QC
1
ช่างถ่ายรูปงาน → ส่งเข้า LINE OA
เช่น งานคอนกรีต, ฉาบปูน, ระดับ, สี, ไฟฟ้า, ประปา, งานตกแต่ง
2
n8n → Supabase Storage → Hub → GPT-4o Vision
AI เทียบกับรูปมาตรฐาน 7 หมวด (14 รูปอ้างอิงจาก checklist จริงของ Finnhouses)
3
รับผลตรวจกลับใน LINE
severity (low/high), suggested_action, confidence score — ภายใน ≤15 วินาที
4
กดปุ่ม "✅ ตรง / ❌ ไม่ตรง"
ต่อท้ายทุกผลตรวจ — ช่วยระบบเก็บ feedback ว่า AI ตัดสินถูกไหม เพื่อปรับปรุงต่อในอนาคต
การแยกประเภทคอนกรีต (Calibration Jun 28)
A) โครงสร้าง (ฐานราก/เสา) — ผิวขรุขระ/รอยแบบไม้ = ปกติ ไม่ใช่ defect (defect จริงคือ honeycombing ≥1cm)
B) พื้น/ทางเดิน — ผิวขรุขระ = defect
C) Pre-pour — ตรวจเหล็ก + แบบหล่อ ไม่ใช่ผิวคอนกรีต
💡 QC Feedback Loop เป็นจุดแรกที่ระบบเริ่มเก็บข้อมูล "AI ตัดสินถูก/ผิด" — ยังไม่มี dashboard สรุป % ความแม่นยำ (มาทีหลังเมื่อข้อมูลสะสมพอ) แต่ทุกปุ่มที่กดมีค่าต่อการพัฒนาระบบในอนาคต

🔧 แก้ปัญหาเบื้องต้น

ปัญหาที่พบบ่อยและวิธีแก้อย่างง่าย

❌ โพสต์ Facebook ไม่ได้
สาเหตุที่พบบ่อย: FB Page Token หมดอายุ
แก้: ต่ออายุ Token ตาม section "ต่ออายุ FB Token" ด้านบน
❌ Blog Runner ค้างนาน / Telegram Health Alert ยิงซ้ำ
เช็ค: System Health Check workflow จะแจ้งเตือนซ้ำทุก 30 นาทีถ้า Blog Runner ค้าง
สาเหตุที่พบมาแล้ว: WF1 รันสำเร็จแต่โดน Publish Guard บล็อก (slug สั้นเกินไป) แล้วไม่มีใครรู้เพราะไม่แจ้งกลับ Hub — แก้แล้ว (Jul 13) ตอนนี้ถ้าโดนบล็อกจะ notify กลับทันที
ถ้าเจออีก: เปิด n8n → Executions → ดูว่า WF1 ไป branch ไหน (Published / Blocked) → ถ้าค้างจริง กด Manual Reset ใน Dashboard
❌ Blog ไม่ขึ้น WordPress
เช็ค: n8n → Executions → ดู WF1 ว่า error อะไร
สาเหตุที่พบบ่อย: Blog Queue ว่าง (ปกติ auto-refill แต่เผื่อไว้) / WordPress REST API ปิดอยู่
แก้: เติม Blog Queue ใหม่ / ตรวจสอบ WordPress admin
❌ Dashboard ไม่แสดงข้อมูล Lead
แก้: รีโหลดหน้า (Ctrl+R) — Dashboard poll Supabase ทุก 30 วินาที
ถ้ายังไม่แสดง: เช็ค Supabase → Table Editor → leads ว่ามีข้อมูลไหม
❌ n8n workflow ไม่รัน / error
เช็ค: railway.app → Primary service → ดู logs
แก้: ถ้า Primary หยุด → Restart
ถ้า execution error → n8n → Executions → คลิก execution ที่ error → ดู node ที่แดง

หมายเหตุ: ระบบใช้ own mode — Primary รับผิดชอบ execution ทั้งหมด ไม่มี Worker/Redis แล้ว
❌ WordPress ไม่อัพเดทหลัง upload
สาเหตุ: PHP OPcache — server cache PHP ไว้ 5 นาที
แก้: รอ 5 นาที แล้วรีโหลด หรือ WordPress Admin → Settings → Purge Cache
❌ Telegram ไม่แจ้งเตือน
เช็ค: Railway Hub → Variables → ว่ามี TELEGRAM_BOT_TOKEN ไหม
เช็คอีก: n8n Telegram node ว่า Chat ID ถูกต้อง (8589960853)
เช็คอีก: workflow ที่เกี่ยวข้อง → Published อยู่ (ไม่ใช่ Draft)
❌ Market Intel ส่งแล้วไม่มีผลใน Telegram
เช็ค: n8n → Market Intelligence Collector v2 (ADR-005) → Published
เช็คอีก: n8n → Executions → ดู execution ล่าสุด error ที่ node ไหน
💬 ถ้าแก้ไม่ได้เอง — บอก Claude โดยอธิบายว่า "เกิดอะไร → ทำอะไรไปแล้ว → เห็น error อะไร" พร้อม screenshot จะช่วยได้เร็วที่สุด
