3. Design Principles

🚦
Single Entry Point
  • Dashboard ไม่เรียก AI โดยตรง
  • Dashboard ไม่เรียก Supabase โดยตรง
  • Dashboard ไม่เรียก n8n โดยตรง
  • ทุก request ผ่าน Hub เท่านั้น
🤖
AI Gateway
  • Hub เลือก AI provider อัตโนมัติ
  • Fallback: OpenAI → Claude → Gemini
  • Cost budget per request type
  • No provider lock-in
📦
Separation of Concerns
  • n8n = automation only
  • Supabase = storage only
  • WordPress = publishing only
  • LINE/FB/TG = output channels only
🔌
Hexagonal Architecture
  • Core domain ไม่รู้จัก infrastructure
  • Ports = interfaces ใน core
  • Adapters = implementation ข้างนอก
  • Swappable ทุก external service
📡
Event-Driven
  • Business events ผ่าน Event Bus
  • Side effects แยกออกจาก core logic
  • Telegram/logging เป็น subscribers
  • Async by default
🔒
Incremental Migration
  • ไม่ break existing endpoints
  • Migrate module ทีละตัว
  • v1 และ v2 รันพร้อมกันได้
  • Feature flag ควบคุม rollout

4. Module Responsibilities

🚪
API Gateway
Presentation Layer
จุดเข้าเดียวของทุก HTTP request — validate, authenticate, route
  • CORS policy enforcement
  • x-hub-token authentication
  • Request validation (Zod schema)
  • Rate limiting per endpoint
  • Route → Controller mapping
  • Error response normalization
  • Request logging
🤖
AI Gateway
Application Layer
Brain ของ platform — จัดการ AI providers ทั้งหมด
  • Provider selection (task-based)
  • Automatic fallback chain
  • Token budget per request type
  • Cost tracking + daily budget guard
  • Prompt template management
  • Response normalization
  • Retry with exponential backoff
📡
Event Bus
Application Layer
In-process pub/sub — decouples business events จาก side effects
  • Typed domain events
  • Synchronous + async subscribers
  • Event history (last 100)
  • Dead letter queue (failed handlers)
  • Subscriber registration
  • Error isolation per subscriber
⚙️
Workflow Manager
Application Layer
Orchestrates business workflows — blog, FB, QC, property
  • Blog run orchestration
  • FB queue management
  • QC inspection pipeline
  • Property review flow
  • n8n webhook dispatch
  • Workflow state tracking
  • Concurrency control
🧠
Memory Manager
Infrastructure Layer
ระบบ state และ data access ทั้งหมดของ Hub
  • Hub state (hub_state table)
  • In-memory cache (TTL-based)
  • Run history management
  • Content frames fetching
  • Repository Pattern implementations
  • Optimistic locking
🏥
Health Center
Application Layer
Proactive monitoring ทุก 30 นาที — แจ้งก่อนเกิดปัญหา
  • Supabase connectivity check
  • FB Backend health check
  • Blog Runner stuck detection
  • DLQ new items detection
  • Alert deduplication
  • Telegram alert dispatch
  • /api/health endpoint
🔐
Authentication
Presentation Layer
Token validation — ทุก request ต้องผ่าน
  • x-hub-token timing-safe compare
  • Route-level auth middleware
  • Webhook signature verification (LINE)
  • Auth bypass for health endpoints
⚙️
Configuration
Infrastructure Layer
Centralized config — single source of truth สำหรับ env vars ทั้งหมด
  • Env var validation at startup
  • Typed config object (no process.env spread)
  • Missing required var = fail fast
  • Config injection via DI container

5. Architecture Layers (Clean Architecture)

Dependency Rule: outer layers depend on inner — never the reverse
Infrastructure (Adapters)
SupabaseAdapter · N8nAdapter · TelegramAdapter · OpenAiAdapter · ClaudeAdapter · GeminiAdapter · WordPressAdapter · LineAdapter
← ไฟล์ที่เปลี่ยนบ่อยที่สุด → ไม่กระทบ core
↑ implements interfaces from ↓
Application (Use Cases + Ports)
RunBlogUseCase · IngestQcUseCase · PublishFbUseCase · RunHealthCheckUseCase · IAiProvider · IStateRepository · IWorkflowEngine · INotifier
↑ depends on ↓
Domain (Entities + Events)
BlogRun · QcInspection · Lead · HubState · BlogRunStarted · QcCompleted · LeadReceived
Zero external dependencies — Pure TypeScript
