งานประจำวัน

01 · เปิด Dashboard ตรวจสถานะ Blog / FB, รายการค้างและข้อความผิดพลาด แล้วดู execution ที่ตรง run ID ก่อนสั่งซ้ำ
02 · เปิด CRM ติดต่อ lead และอัปเดต stage/บันทึก; การปิด lead ไม่สร้างสัญญาหรือดีลอัตโนมัติ
03 · ตรวจเนื้อหาและข้อมูลทรัพย์ก่อนเผยแพร่ ตรวจผลที่ WordPress / Facebook อีกครั้งหลัง API ส่งผล
04 · เมื่อมีข้อมูลจริงเพิ่ม ให้บันทึกดีล ต้นทุน หรือ human feedback ในหน้าที่เกี่ยวข้อง

CRM และ AI Content

CRM

01 · เพิ่ม lead หรือ import CSV และตรวจหน่วย consult / list ให้ถูกต้อง
02 · ติดตาม new → followup → qualified → closed พร้อม notes และผลการติดต่อ
03 · ข้อมูลบันทึกผ่าน /api/leads ไม่ควรตีความชื่อ source เก่า “Budget Tool” ว่าฟอร์มสาธารณะยังทำงาน

Content Studio

01 · เลือก Keyword / Blog URL / Listing ตามแหล่งข้อมูลที่มีจริง; Positioned ใช้กลุ่ม resale หรือ inspection ตาม UI
02 · Generate แล้วตรวจภาษา ราคา รายละเอียดและ CTA; History/Taste เป็นข้อมูลอ้างอิง ไม่ใช่หลักฐานการฝึกโมเดล
03 · เลือก Copy/Save, Post to Facebook หรือเตรียม Queue; โพสต์ทันทีและโพสต์จาก Queue ใช้คนละเส้นทาง

ดีลรีโนเวทขายและการประเมินที่ดิน

01 · ใน Deals เพิ่มชื่อดีล ราคาซื้อ งบรีโนเวท ราคาตั้งขาย และ site ที่เกี่ยวข้อง (ถ้ามี)
02 · ย้ายขั้น evaluating → renovating → listed → closed; กรอกต้นทุนรีโนเวทและราคาขายจริงเมื่อมีหลักฐาน
03 · ROI ในโค้ด = (ราคาขาย − ราคาซื้อ − ค่ารีโนเวท) ÷ (ราคาซื้อ + ค่ารีโนเวท) × 100 ยังไม่รวมภาษี ดอกเบี้ย ค่าถือครองหรือค่านายหน้าแยกต่างหาก
04 · ใช้ Land Analyzer สำหรับซื้อที่ดินพัฒนาเพื่อขายและบันทึก projects แยกจาก reno_deals; ไม่มีการสร้างดีลจาก Land Analyzer ตาม ADR-027

ตรวจทรัพย์ก่อนเผยแพร่

01 · Dashboard → ทรัพย์รอ Review: ตรวจชื่อ ประเภท ราคา ทำเลและรายละเอียดให้ตรงต้นทาง
02 · อัปโหลด COVER ให้ได้ media_id มากกว่า 0; gallery ที่ใส่ไว้ต้องอัปโหลดสำเร็จ ไม่ใช่แค่ URL โค้ดไม่ได้บังคับว่าต้องมีครบ 3 รูปเสมอ
03 · กด Approve แล้วตรวจ URL/ผลตอบกลับ; Dismiss เป็นการเปลี่ยนข้อมูล ไม่ใช่ซ่อนเฉพาะเบราว์เซอร์

QC / Quality Gate / Market calibration

QC ตรวจภาพงานก่อสร้าง ส่วน Quality Gate ตรวจบทความ เป็นคนละชุดข้อมูลและคนละ feedback อย่ารับรองเวลาตอบคงที่ 15 วินาที

Quality Gate ใน Dashboard กดยืนยันการตัดสินใจถูก/ผิดได้; QC feedback ผ่าน LINE ตาม workflow ที่ตั้งไว้ และ Market Intel มีหน้า Calibration การกด feedback บันทึกผลประเมิน ไม่ได้ปรับ prompt หรือฝึกโมเดลเอง เกณฑ์ ≥10 feedback เป็นเกณฑ์ UI ไม่ใช่การรับรองทางสถิติ

ADR-016 แก้ขอบเขต brand แล้วใน PR #3: บทความให้ความรู้สร้างบ้านผ่านได้; บล็อกเมื่ออ้างบริการรับจ้างสร้างบ้านหรือ CTA ที่สื่อเช่นนั้น ยังต้องตรวจภาษา ข้อเท็จจริง โครงสร้างและเนื้อหาซ้ำ

ยังต้อง export workflow ที่ active เพื่อตรวจ writer / rewriter / gate และรันทดสอบทั้งกรณีผ่านและบล็อก การ merge เอกสารไม่แก้ prompt ใน n8n อัตโนมัติ Policy เดิมใน ADR ยังให้ AI infrastructure/parse error เป็น fail-open ซึ่งต้องแยกจากการตรวจเนื้อหาผ่านจริง

Assistant และข้อมูลที่จำได้

Assistant ส่งข้อความและประวัติในหน้าเว็บไป /api/assistant ซึ่งเรียก Claude Sonnet 4.6 และเลือก tools อ่าน Hub / Supabase / Brains ได้ คำสั่งเขียนมีเพียงรัน Blog กับ FB queue โดยมีปุ่มยืนยันก่อนเรียก

ประวัติอยู่ใน React state; reload แล้วไม่กู้แชทจากฐานข้อมูล ไม่มี tool สร้างหรือแก้ดีลจากแชท ข้อมูลสมมติในบทสนทนาจึงไม่ใช่ข้อมูลดีลที่บันทึกแล้ว

ข้อกำหนดห้ามตอบด้วยข้อมูลนอกระบบอยู่ใน prompt แต่โค้ดยังส่งข้อความที่โมเดลสร้างกลับมา จึงยังไม่ใช่การบังคับคำตอบจากหลักฐานฝั่งเซิร์ฟเวอร์อย่างสมบูรณ์ ปุ่มยืนยันคำสั่งไม่ทดแทนระบบตรวจสิทธิ์ผู้ใช้

Market Intel และ Brains

ส่งข้อความตลาดพร้อมพื้นที่ผ่าน /market-intel หรือแท็บที่เกี่ยวข้อง แล้วตรวจว่า workflow เขียนข้อมูลสำเร็จ อย่าถือว่ารับ webhook แล้วเท่ากับบันทึกครบทุกตาราง

Brains เป็นตัวอ่านรวมข้อมูลเดิม ไม่ใช่ฐานข้อมูลใหม่และไม่ได้ฝึกโมเดลเอง อ่าน market insights, summary, area memory, buyer signals, deals, QC และ content frames แต่ไม่อ่านประวัติแชท, projects หรือ BOQ ใน endpoint นี้

ตัวกรองพื้นที่ใช้กับ market insights, summary, area memory และ deals เท่านั้น ส่วน buyer signals, QC และ content frames ไม่ได้กรองตามพื้นที่ ค่า verified_insights หมายถึง confidence ≥ 4 ไม่ใช่การยืนยันโดยมนุษย์ จำนวนที่คืนเป็นผลค้นจำกัดจำนวนต่อแหล่งข้อมูล ไม่ใช่ยอดรวมทั้งระบบ

อาการ/งาน ตรวจอย่างไร
Facebook โพสต์ไม่ได้ อ่านข้อความผิดพลาดจากหน้าเว็บ ตรวจ FB_BACKEND_URL และ backend logs ก่อนสรุปว่า token หมดอายุ ตรวจอายุ/สิทธิ์ token จากบัญชีจริง ไม่ใช้วัน Aug 2 เดิม
Blog ค้าง หา execution/run ID และ callback ว่าไป published, blocked หรือ error; ตรวจว่ารันเดิมหยุดแล้วก่อน reset เพื่อไม่สร้างงานซ้ำ
ไม่พบข้อมูล แยกผลค้นว่างออกจาก API error; ตรวจช่วงวันที่ ตัวกรองและสิทธิ์ของ service อย่าแทน error ด้วยศูนย์
n8n ไม่รันตามเวลา ตรวจ active revision, trigger, timezone, execution ล่าสุดและบริการที่ใช้อยู่ ไม่ยึดเวลา 09:05 หรือรูปแบบ hosting จากคู่มือเก่า
WordPress ไม่แสดงผลใหม่ ตรวจ post/media response, URL และ cache ตาม hosting จริง ไม่ถือว่าต้องใช้ cPanel หรือรอ cache 5 นาทีเสมอ
ทบทวนค่าใช้จ่าย ยอดผู้ใช้แจ้ง: OpenAI $5 + Claude $5 + Railway $10–15 = $20–25/เดือน; n8n ฟรี ไม่รวมว่า API AI ฟรีด้วย ยังไม่มี hard cap รวมที่ยืนยันได้
